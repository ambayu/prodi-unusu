Berikut saya susun PRD lengkap Sistem Manajemen Website Multi-Prodi Universitas Nusa Utama (UNUSU) berdasarkan seluruh pembahasan kita.

Saya tetapkan arsitekturnya sebagai Monolithic Fullstack Application: satu aplikasi, satu codebase, satu backend, satu database, dan banyak domain website Prodi.

Stack yang digunakan:

    Frontend: React + TypeScript + Vite.

    Backend: Node.js + Express + TypeScript.

    ORM: Prisma.

    Database: MySQL.

    UI: Tailwind CSS + shadcn/ui.

    Authentication: Session/JWT berbasis role dan hak akses.

    Deployment: Ubuntu VPS + Nginx + PM2.

    Architecture: Modular Monolith, bukan microservices.

Saya juga memasukkan kebutuhan paling penting: setiap Prodi dapat memiliki desain website yang benar-benar berbeda melalui Widget Builder, tanpa harus membuat aplikasi terpisah.

1. OVERVIEW
1.1 Latar Belakang

Universitas Nusa Utama (UNUSU) memiliki beberapa fakultas dan program studi yang membutuhkan website resmi masing-masing dengan domain berbeda.

Pengelolaan website secara terpisah menyebabkan beberapa permasalahan:

    Setiap website membutuhkan instalasi aplikasi sendiri.

    Pembaruan fitur harus dilakukan berulang kali.

    Pengelolaan konten tidak terpusat.

    Pengelolaan akun administrator sulit dikontrol.

    Desain website setiap Prodi sulit diseragamkan maupun dikembangkan secara independen.

    Pemeliharaan server dan database menjadi lebih kompleks.

Untuk mengatasi permasalahan tersebut, diperlukan sebuah aplikasi terpusat yang mampu mengelola banyak website Prodi menggunakan satu aplikasi fullstack.

Sistem menyediakan portal administrasi pusat melalui:

https://prodi.unusu.ac.id

Sementara itu, masing-masing website publik tetap menggunakan domain sendiri, misalnya:

    https://tif.unusu.ac.id

    https://sin.unusu.ac.id

    https://iko.unusu.ac.id

    https://manajemen.unusu.ac.id

    https://agribisnis.unusu.ac.id

Seluruh website menggunakan backend dan database yang sama, tetapi mempunyai konten, pengguna, konfigurasi, dan desain yang independen.
1.2 Tujuan Sistem

    Membangun satu aplikasi untuk mengelola seluruh website Program Studi UNUSU.

    Memusatkan autentikasi dan administrasi melalui satu portal.

    Memberikan akses terpisah kepada administrator masing-masing Prodi.

    Menyediakan Website Builder berbasis widget.

    Memungkinkan setiap Prodi membuat desain landing page yang berbeda.

    Menyediakan CMS untuk mengelola informasi akademik dan administrasi Prodi.

    Mempermudah penambahan Prodi dan domain baru tanpa membuat aplikasi baru.

    Mengurangi biaya infrastruktur dan pemeliharaan.

1.3 Konsep Utama

Sistem menggunakan konsep:

One Application – Multiple Websites – Independent Management.

Artinya:

    Satu aplikasi React.

    Satu backend Node.js.

    Satu database MySQL.

    Satu sistem autentikasi.

    Banyak domain.

    Banyak tenant.

    Setiap tenant memiliki data dan desain independen.

Tidak ada kebutuhan untuk melakukan instalasi aplikasi baru ketika menambahkan website Prodi.
1.4 Target Pengguna

    Administrator Universitas.

    Administrator Fakultas (jika modul Fakultas diaktifkan).

    Administrator Program Studi.

    Editor konten.

    Pengunjung website.

    Calon mahasiswa.

    Mahasiswa.

    Dosen dan tenaga kependidikan.

https://sin.unusu.ac.id

        ↓

        ↓

Express membaca hostname
        ↓

Domain Resolver mencari domain
        ↓

Database menemukan tenant Sistem Informasi
        ↓

Mengambil konfigurasi website
        ↓

React merender website Sistem Informasi

Domain Resolver wajib:

    Mengenali hostname.

    Memeriksa domain aktif.

    Gunakan Modular Monolith, jangan memisahkan frontend dan backend menjadi dua repository atau dua deployment aplikasi.

    Melihat preview desktop, tablet, dan mobile.

    Menyimpan perubahan sebagai draft.

    Mempublikasikan perubahan.

Gunakan sistem widget registry dengan daftar komponen yang sudah ditentukan dan tervalidasi.

Jangan mengizinkan administrator memasukkan JavaScript atau HTML sembarangan untuk membuat widget.

Setiap website memiliki konfigurasi landing page sendiri yang tersimpan di database.

Konfigurasi website utama harus terpisah dari seluruh konfigurasi website prodi.
4. Pemisahan Layout dan Komponen

Aturan wajib:

    MainWebsiteLayout tidak boleh menggunakan ProdiWebsiteLayout.

    MainNavbar tidak boleh menggunakan ProdiNavbar.

    MainFooter tidak boleh menggunakan ProdiFooter.

    MainLandingPage tidak boleh menggunakan ProdiLandingPage.

    Perubahan desain website utama tidak boleh memengaruhi website prodi.

    Perubahan desain satu prodi tidak boleh memengaruhi prodi lainnya.

Komponen dasar yang sifatnya umum seperti Button, Input, Modal, dan utilitas boleh digunakan bersama apabila sesuai.

Jangan melakukan duplikasi komponen secara berlebihan. Namun, jangan pula memaksakan komponen yang memiliki kebutuhan desain dan perilaku berbeda menjadi satu komponen generik.

Gunakan tabel domain di database untuk menentukan website yang harus ditampilkan.

Jangan melakukan hardcode domain satu per satu di frontend.
6. Pemisahan Administrator

Portal login administrator berada di:

prodi.unusu.ac.id

Portal tersebut merupakan pusat pengelolaan sistem.

Administrator memiliki hak akses sesuai peran:

    Super Admin: mengelola seluruh website, domain, pengguna, dan konfigurasi.

    Main Website Admin: mengelola website utama UNUSU.

    Faculty Admin: opsional, mengelola program studi di bawah fakultasnya.

    Prodi Admin: mengelola website prodi yang menjadi tanggung jawabnya.

    Content Editor: mengelola konten sesuai izin yang diberikan.

Dashboard administrasi website utama dan dashboard administrasi prodi boleh memiliki navigasi serta menu yang berbeda sesuai kebutuhan pengelolaan.

8. Ketentuan Implementasi

Sebelum melakukan perubahan:

    Pelajari struktur proyek yang sudah ada.

    Periksa routing, layout, komponen, Prisma schema, dan sistem autentikasi.

    Identifikasi bagian yang masih mencampurkan website utama dengan website prodi.

    Buat rencana refactoring tanpa merusak fitur yang sudah berjalan.

    Pastikan seluruh kebutuhan pemisahan tampilan dapat dipenuhi.

Jangan langsung mengubah seluruh proyek tanpa memahami struktur existing.

Jika proyek sudah berjalan, pertahankan fitur yang tidak berkaitan dengan perubahan ini.
9. Kriteria Keberhasilan

Implementasi dianggap berhasil apabila:

    Website utama memiliki navbar, footer, layout, dan landing page tersendiri.

    Website prodi memiliki navbar, footer, layout, dan landing page tersendiri.

    Setiap prodi dapat memiliki desain landing page yang berbeda.

    Administrator dapat mengelola section dan widget sesuai hak akses.

    Perubahan website utama tidak mengubah website prodi.

    Perubahan satu prodi tidak mengubah prodi lain.

    Semua domain berjalan dalam satu aplikasi monolitik.

    Seluruh data tetap terisolasi berdasarkan website/tenant.

    Portal administrasi tetap terpusat di prodi.unusu.ac.id.
